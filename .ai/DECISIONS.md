## 决策：投稿审核 fail-closed（唯一路径）

- **状态：** Accepted
- **日期：** 2026-09
- **决策：** 所有投稿（单条 / 批量 / 修改）统一走机审编排 `runReview`；AI 审核任何异常（未配置 / 网络失败 / 返回不可解析 / `uncertain`）一律保持 `pending` 转人工，绝不默认放行。
- **理由：** 内容安全优先于发布便利；宁可人工兜底，不可自动放行风险内容。
- **权衡：** 增加人工审核工作量；换来内容安全底线。
- **重新评估的条件：** 引入可靠的自助审核通道或产品策略明确要求降低人工占比时。

## 决策：用户 / 管理员双 cookie + JWT（jose）认证分离

- **状态：** Accepted
- **日期：** 2026-09
- **决策：** 前台用户与后台管理员使用独立 cookie，JWT 内校验 role；写接口第一行校验会话，数据层操作带 `user_id` 归属条件。
- **理由：** 权限边界清晰，防越权；httpOnly cookie 降低 XSS 窃取风险。
- **权衡：** 双 cookie 增加一点复杂度；换来后台与前台权限严格隔离。
- **重新评估的条件：** 引入 OAuth / SSO 等统一身份体系时。

## 决策：限流前置 Edge middleware + Upstash Redis，内存限流降级为兜底

- **状态：** Accepted（取代早期"全内存限流"方案）
- **日期：** 2026-09
- **决策：** 注册 / 登录 / 投稿 / 批量等敏感接口的限流统一放在根目录 `middleware.ts`（Edge），计数用 @upstash/ratelimit + Upstash Redis（REST，Edge 兼容）；登录用户以 JWT 解析出的用户 id 为 key，匿名以 IP（x-forwarded-for 首项）为 key；命中返回 429 + Retry-After；静态资源 / `_next` 放行。未配置 Redis 时 middleware 降级放行，`lib/rate-limit.ts` 内存滑动窗口作为单实例兜底。
- **理由：** 请求到达业务代码前拦截，省资源；Redis 共享状态支持多实例；降级 + 兜底保证不裸奔也不误伤。
- **权衡：** 依赖外部 Redis（当前 UPSTASH 凭证为空，实际处于降级态）；Edge 不能查库，用户 id 只能信 JWT。
- **重新评估的条件：** 部署确定为单实例且不希望引入 Redis 时，可回退到纯内存方案。

## 决策：SEO 对外域名绝不输出 localhost

- **状态：** Accepted
- **日期：** 2026-09
- **决策：** sitemap / robots / metadataBase / JSON-LD 统一经 `resolveSiteUrl()` 解析域名（后台 `site_url` → 环境变量 `SITE_URL`），localhost / 非法值一律视为未配置；未配置时 sitemap 空、robots 禁止抓取。sitemap / robots 用 `revalidate = 86400` 每日重建，sitemap 收录动态路由（分类页、文案详情页等）。
- **理由：** 防止向搜索引擎输出本机地址污染索引；域名由管理员后台自定义。
- **权衡：** 未配置域名时 SEO 输出为空；换来不会收录 localhost 的错误 URL。
- **重新评估的条件：** 引入按请求 Host 动态生成（会牺牲静态缓存）时。

## 决策：移除文案标签（tags）功能，数据归档非破坏

- **状态：** Accepted
- **日期：** 2026-09（迁移 002）
- **决策：** 全链路移除标签（DB 列 / ORM / API / 类型 / 校验 / admin UI / 详情页 / 搜索筛选）；迁移先把 tags 数据归档到 `wenan_copy_tags_archive`，再删列与 GIN 索引，并提供 rollback。

- **权衡：** 丢失标签维度（可从归档恢复）；换来模型与检索更简单。
- **重新评估的条件：** 产品重新需要多维度归类时（优先评估独立关联表而非 TEXT[]）。

## 决策：四主题体系 + 首帧防 FOUC，禁用 body filter/transform

- **状态：** Accepted
- **日期：** 2026-09
- **决策：** 全站支持 light / dark / system（默认跟随系统）/ neon（彩蛋，复古街机像素风）；选择持久化 cookie + localStorage；根 layout 内联脚本在首帧前设置 `data-theme`，SSR/CSR 一致防 hydration 冲突。主题动效只允许 background-position / text-shadow / opacity。
- **理由：** 深色 / 浅色是基础体验，彩蛋增强个性；防 FOUC 与 hydration 错误是硬性要求。
- **权衡：** 彩蛋主题增加 CSS 体积与维护；动效受限（不能用 filter/transform，因其破坏 fixed 定位，见 TROUBLESHOOTING）。
- **重新评估的条件：** 彩蛋反响不佳时可替换，但 body filter/transform 禁令保持。

## 决策：.env 精简，非必要配置集中到 admin「站点设置」

- **状态：** Accepted
- **日期：** 2026-09
- **决策：** .env 只保留基础设施与密钥（DATABASE_URL、管理员凭据、JWT_SECRET、TTL、COOKIE_SECURE、可选 Redis / SITE_URL）；站名、标题后缀、SEO、页脚、审核开关与违禁词、AI 参数、跑马灯内容 / 速度等全部由后台站点设置接管。

- **权衡：** 依赖设置表与缓存（30s）；密钥仍留在环境（不进 DB）。
- **重新评估的条件：** 某项配置确需在构建期 / 多环境差异化时。

## 决策：Nginx 生产配置纳入仓库并要求随路由同步

- **状态：** Accepted
- **日期：** 2026-09
- **决策：** `Linux/nginx/production.conf` 纳入版本管理（含页面 / `_next` / `/api` / sitemap / robots / 图片优化 / WebSocket upgrade 的转发注释），`Linux/README.md` 登记规则；新增路由 / 服务必须同步更新。

- **重新评估的条件：** 改为模板化 / 自动化生成 Nginx 配置时。

## 决策：投稿软删除 + 注销匿名化 + 异步任务

- **状态：** Accepted
- **日期：** 2026-09
- **决策：** 删除一律软删（`deleted_at`）进回收站，冷静期 30 天可恢复、到期 cron 物理删除；被收藏数 ≥ 阈值（默认 3）的文案受社区保护、作者不可单方面删除；批量删除 / 注销写 `wenan_deletion_jobs`，响应 202 后用 `after()` 分块（50/批）执行，`/api/cron/deletion-jobs`（CRON_SECRET）兜底；注销默认「内容保留并匿名化」（approved 解 user_id，pending/rejected 软删，用户置 deactivated_at、登录拒绝）。
- **理由：** 防止用户（含养号-删库）一次性物理删除几百条导致社区内容蒸发、收藏死链、锁表；兼顾被遗忘权与社区利益。
- **权衡：** 软删 + 任务表带来额外复杂度与存储；阈值可能让部分作者不满（可申诉/联系管理员）；`after()` 依赖常驻进程，故配 cron 兜底。
- **重新评估的条件：** 引入对象存储 / 独立 worker 队列，或阈值、冷静期需按运营数据调整（均为后台可配）。
